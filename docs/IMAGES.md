## 一、实测事实（不是推测）

`cargo run --bin multimodal`（probes/api），两次不同 nonce 数字完全一致：

| | DeepSeek | Kimi K3 | GLM |
|---|---|---|---|
| `content` 用数组（只放 `text` 块） | ✓ | ✓ | ✓ |
| 数组形态本身的 token 开销 | **0** | **0** | **0** |
| `image_url` 块 | ✗ 400 | **✓** | ✗ 400 |
| 模型真的看见了 | — | ✓ 答对图内四位数 | — |

被拒的两家原文——**是形状不认识，不是能力开关**：

```
DeepSeek  400  unknown variant `image_url`, expected `text`
GLM       400  1210  messages.content.type 参数非法，取值范围 ['text']
```

图片在 Kimi 上**进缓存前缀**且对仅扩展匹配友好：原样重发 `cached=4120/prompt=4132`
（99.7%），末尾追加一轮之后 `cached` 仍是 4120。

图片 token **随面积长，不是固定开销**：4x/10x/24x 三档分别 16 / 48 / 248 token
（大档约 690 像素每 token）。**别把 48 当成「图很便宜」**——那是 270×110 的小图，
一张 4K 照片外推是万级 token。

## 二、官方文档给的（platform.kimi.com）

- 图片有**两种**给法：内联 `data:image/png;base64,...`，或先上传 `POST /v1/files`
  （`purpose: "image"`）拿 id，再用 `ms://<file-id>`。**公网 URL 不支持。**
- 单文件 ≤100MB，请求体 ≤100MB，推荐图 ≤4K（4096×2160），图片张数无上限。
- 有 token 预估接口（`/docs/api/estimate`）。
- **多轮里图片要不要重发：文档没写。** 缓存文档通篇只谈文本，对图片只字未提——
  §一 那条「图片进缓存」是我们探针量的，文档给不出。

## 三、拍板的决定

| # | 决定 | 理由 |
|---|---|---|
| 1 | **走 `ms://<file-id>`，不内联 base64** | 历史里躺一个短 id 而不是几十 KB base64。落盘、请求体、前缀字节一起省 |
| 2 | **图片进历史就一直在，不做「解析完删掉」** | 见 §四 |
| 3 | **只做图片**，非图片附件不支持 | 范围决定 |
| 4 | **有图才用数组形态**，纯文本消息逐字节不变 | 见 §五 |
| 5 | **file 过期不管** | 一期不处理，见 §六 |
| 6 | DeepSeek / GLM **报 `Adjustment` 降级，不许静默丢图** | 静默丢图 = 用户传了图、模型没看见、回答还挺像样，用户永远发现不了 |

## 四、为什么不做「解析完就移除」

提过这个方案，算完之后否掉了。三条理由，按硬度排：

**一、undo。** 「移除」有两个意思，只有一个能做：字节真从 store 里删 → `/undo`
撤回那一轮时图回不来，**原子状态引擎的四个投影破了一个就是四个都破**；字节留着
只是不进 prompt → 那不叫移除，叫「一个不进 prompt 的标记位」，而那正是
[ROADMAP §四](ROADMAP.md) 已经记着的「压缩与 undo 的窗口对立（P3）」，
且决策 18 已经把压缩三分拍过了。**图片不该另开一套。**

**二、钱上多数时候是亏的。** Kimi 是仅扩展匹配，动历史中段那一轮全价重编码。
按实测数字（命中轮 ≈424 等效 token，分歧轮全价 4084）：

| 图片大小 | 一次性代价 | 每轮省 | 回本 |
|---|---|---|---|
| 48 token（小图） | 3660 等效 | 4.8 | **762 轮** |
| 1.3 万 token（4K 照片） | 3660 等效 | 1300 | 约 3 轮 |

**只有图片 token 跟整个前缀一个量级才回得了本。**

**三、「解析完了」没人判得准。** 模型答了句「这是一张发票」不等于信息都提出来了。
下一轮问「右下角税号是多少」，模型会**照着自己那句描述编，而且不报错**。

**留下的问题（一期不解决，记在这）**：`ms://` 省的是字节不是 token——服务端照样把
图展开成视觉 token，一张 4K 图永久占 128k 窗口的约 10%。用户连传十张图窗口就满了。
真撞上时**归压缩管**（决策 18 的三分），不为图片单开机制。

## 五、为什么是「有图才用数组」

探针证明数组形态零 token 开销，所以恒定用数组也不花钱。但仓里的一贯做法是
**「不用这个功能，逐字节不变」**（065 的 `capabilities`、067 的 MCP 都显式这么做）。

恒定数组要付的代价是真的：`wire::messages` 现有的一批 golden 测试全要改
（`messages.rs` 里 `json!({"role":"user","content":"北京天气"})` 那种），而且所有
在跑的会话前缀一次性作废。

**曾经担心过、现在不成立的风险**：早先认为「有图才数组」会让同一条消息在两种形态间
跳、撞红线 11。定了 §三-2「不移除」之后，一条消息带不带图从写进历史那一刻就定死，
**永远不会变形态**，这个风险不存在。

哪天真要切成恒定数组，探针那条「零开销」结论说明是免费的。

## 六、file 过期：一期不管，但知道自己在赌什么

Moonshot 文档**没写留存期**。过期之后两种可能：

- provider 返回错误 → 走正常错误路径，可见，没问题
- provider 照样 200、只是模型看不见那张图 → **静默**，这是本仓最贵的那类

一期接受这个风险（决定 §三-5）。**二期要做的事记在这**：让历史里那条留一个人看得见
的痕迹，别只剩一个死链。真要查，一次上传 + 隔天重发就知道了。

## 七、`ms://` 是不是把 provider 的东西塞进了 core（红线 12）

**不是，但要按下面这个形状写才不是。**

`ContentBlock::Image` 里那个引用字符串对 core 是**完全不透明的**：core 只存、只原样
传给 adapter，**不 match、不解析、不按前缀分支**。这跟 `ToolCallId` 是同一类——那也是
provider 铸的字符串，core 原样存原样传回，从来没人说它违反红线 12。

红线 12 禁的是**判断**（`match provider` / `if caps.xxx()`），不是禁**数据**。

**会违规的写法**（别这么干）：core 里出现 `if reference.starts_with("ms://")`、
或者按引用形态决定走哪条路。那种判断属于 adapter。

**换 provider 的后果要说清**：`agent-cli` 有 `model_switch.rs`，会话中途换 provider 是
支持的。换到 DeepSeek/GLM 之后那个 `ms://` 引用它们解不了——但那两家**本来也看不了图**，
所以行为跟「一开始就用 DeepSeek」完全一致：走 §三-6 的降级路径，报 `Adjustment`。
**不会拿一串它不认识的字符串去撞 400**，因为降级发生在 encode 里，根本不会进 wire。

## 八、上传发生在哪（这条最容易放错）

**在 HTTP 路由层，`Command` 进 actor 之前。**

排除掉的两个位置，理由是硬约束不是偏好：

- **core / store**：红线 7，不许做 IO。
- **adapter 的 `encode`**：`Provider` trait 的全部方法都是纯函数（`agent-providers`
  的 lib.rs 开头就写着「零 IO」）。
- **`provider_call::start`**：它跑在 **actor 线程**上，而它拆成 start/finish 两半的
  全部意义就是「只做能在 actor 线程上做完的部分」（029 的并行就是这一刀）。往里加
  一次网络上传 = 把所有 agent 的并行掐死。而且上传只需要做一次，不是每轮。

所以：**路由层收到附件 → 上传 → 拿到 id → 带着 id 把 `Command` dispatch 进 actor。**

好处是失败处理干净：上传失败就 400 回客户端，**store 里什么都没发生**，不存在半个状态。

需要 endpoint + api_key——`SessionTemplate`（`bootstrap.rs` 拼的那份）里有
`provider`/`endpoint`/`api_key`/`model` 四个字段。**动手前先确认 `AppState` 拿不拿得到**，
拿不到就把这条路径写进 issue 的实做记录，别绕路。

## 九、红线检查清单（收工前逐条过）

- **红线 3**：新的 `ContentBlock` 变体必须 `Serialize + Deserialize`，且往返相等
  （`message.rs` 已有 `message_roundtrip` 测试，加变体要一起加进去）。
- **红线 5**：字段用 `Arc<str>`，别用 `String`——`store.get()` 每次读整条历史。
- **红线 11**：降级占位文本**会进 prompt**，只能由这个块自己的字段推出来，
  不许有时间戳、计数器、随机 id。带图会话第 2 轮 `predicted == actual`。
- **红线 12**：core 里不许出现任何按引用字符串形态的分支（§七）。
- **红线 9**：`wire/messages.rs` 现在 174 行，加了图片编码可能顶破 300——
  **拆分是本次改动的一部分**，不留「下次再拆」。
- **`--features ts`**：`Adjustment` 挂着 ts-rs 导出，加变体要过一致性测试
