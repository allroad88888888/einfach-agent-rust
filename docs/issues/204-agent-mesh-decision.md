## 一、红线 10 挡的是环，而环今天已经不可能了

红线 10 的无环论证依据的是**边**：`U ∩ D = ∅` + 图恒为树 ⇒ 环不可能
（证明写在 `graph/visibility.rs` 的模块文档）。**环由响应式依赖造成。**

第一层容易看见的过严：`srv:agent/status` 已经是一次**快照读**——运行时调
`session.agent_tree()`、渲染成文本、写进 tool_result（`status_tool.rs:115`），
**调用者的 derived 没有依赖被读方的任何 atom**，图上一条边都没多。它挡兄弟跟环
毫无关系，只是因为红线 10 今天只有一句「跨 agent 读只走两个口」，而那两个口
（`cross_read.rs:59` / `:79`）**同时服务响应式路和快照路**——一刀切把不建边的那条
也切了。

**但第二层更要紧：连响应式那条也造不出环。** 下面这一节是本决策的地基。

### 但真去查了一遍：那个无环证明防的东西，今天已经不可能了

用户 2026-08-18 拍板：**横读全开，包括互相订阅**（响应式那条边也开）。定价之前先把
账查清——**结论是这条几乎白拿，之前把它算贵了。**

`graph/build.rs:71`：

```rust
let DerivedKey::ToolsConverged(agent) = key;
```

**整个系统只有一种 derived。** `Slot` 里每一个都是 primitive，而且这是**类型上的事实**
不是纪律：source 与 derived 是两张按不同键类型索引的 family
（`build.rs:47` / `:53` 的注释原话：「跟 source 分开是为了让『快照只存 primitive』
成为类型上的事实」）。

跨 agent 读读的是 `AtomKey::Agent(id, slot)` —— **永远落在 source family 上，
永远是一个叶子**。而环需要 derived → derived 绕回来。所以：

> **横向响应式读造不出环，跟方向没有关系。**

`U ∩ D = ∅` 那个证明防的是一件在当前实现下已经不可能的事。**幸好它不可能**——
真撞上时 `store/read.rs:151` 是 `panic!("circular dependency detected")`，不是错误
返回；一个模型可触发的 panic 是完全不能接受的形状。

### 拍板：横读全开，红线 10 从「方向约束」改成「**边只许指向 primitive**」

> **跨 agent 读不限方向；但只能读 primitive 槽位。**
> 要跨 agent 读一个 derived，先回来改这条红线。

新判据比旧的**更简单也更强**：primitive 没有出边 ⇒ 跨 agent 的边全是长度 1 的悬边 ⇒
环在结构上不可能。且它今天由类型系统守着（读口收的是 `Slot`，`Slot` 只映射到
source family），不靠人记。

三条路的落点：

| 路 | 口 | 方向 | 建边 |
|---|---|---|---|
| **响应式读**（订阅：目标一变，我这边自动重算） | **新增** `Session::read_agent` | **不限** | 建，但只指向 primitive |
| **快照读**（一次取值，进 tool_result） | 新增 `Session::peek_agent` | **不限** | 不建 |
| **写**（往别人的 `Inbox` 投递） | `deliver`，走命令层 | **不限** | 不建 |

`read_ancestor` / `read_descendant` **保留不删**：它们现在是 `read_agent` 加一道
方向断言的薄封装。029 的汇聚确实是往下的，让调用点把这个意图说出来是有价值的，
而且现有调用方与测试**一行都不用改**（照 200 保留无参 `undo_turn()` 的同一条理由：
一次全改是无谓的爆炸半径）。

### `Visibility` 三态收成两态

方向不再是约束之后，`Upward` / `Downward` 的区分不再 gate 任何东西——留着就是一个会
骗人的字段。收成：

```rust
pub enum Visibility {
    /// 别的 agent 读得到（任意方向）
    Shared,
    /// 只有自己读得到 —— 这个 agent 的内部账本
    Private,
}
```

**穷举 match 保留**（`visibility.rs:59` 无通配，新增槽位不站队直接编译不过）——那是
红线 10 唯一能被编译器守住的部分，跟方向没关系，不能一起删。`U ∩ D = ∅` 那条测试
换成两条新的：**每个槽位恰好站一边**，以及**跨 agent 读口只接受 primitive**。

**`Private` 的含义一个字不变**：预算、消息号计数器、前缀镜像、压缩账、收件箱
（`visibility.rs:50`）。别人读你的 `TurnsUsed` / `Summaries` / `Inbox` 照旧拒。

### 真正要花钱的是两样，都不是环

1. **`Messages` 从 Upward-only 变成 Shared**，意味着**任何 agent 能读任何 agent 的
   完整对话正文**。这不是正确性问题，是 token 与暴露面问题：读一个兄弟的全程 transcript
   进自己的 prompt，一次就能把一轮的成本翻几倍。205 里 `Messages` 要单独拿出来重新
   站队，并且**默认不给模型开这条路**——模型侧要正文有 `collect`（领结果）和
   `send`（要什么问什么），两条都是有边界的。
2. **等待环（死锁）**：这是真订阅唯一的新危险，跟依赖环是两回事，见下。

### 订阅这件事本身：新危险是死锁，不是环

模型建不了 derived——它只有工具。所以「订阅」在模型面上的形状是一个工具：

| | |
|---|---|
| `srv:agent/await` | 入参 `{ id, until }`。调用者这个工具槽保持 `Pending`，直到 `id` 到达 `until`（`Done` / `Failed` / 任一终态） |
| 内部 | 一个新 derived，读目标的 `Status`（primitive，叶子）。**不造依赖环**——上面刚证过 |
| 目标 | 本轮任意活 agent，**含兄弟**。这就是「互相订阅」落地的地方 |

**但两个 agent 互相 await 就是死锁**：A 的槽等 B 变 `Done`，B 的槽等 A 变 `Done`，
两边都不会动。而且它**不 panic、不报错**——泵的静止条件是
`calls.is_empty() && mcp_calls.is_empty()`（`runner.rs:291`），两个 agent 都在等
derived、都没有 provider 调用在飞，于是**泵会安静地返回，留下两个永远 `ToolsPending`
的槽**。`runner.rs` 模块文档管这叫无定义状态。

**这是决策 1 真正的代价，也是它唯一的代价。** 换掉的不是无环保证（那个白拿），
是要新建一张**等待图**并在上面查环：

- 谁在等谁，是**状态**（新槽位，journaled）——不是内存里的一张表。恢复之后还得查得了环。
- `await` 建立等待关系**之前**先跑一次可达性：目标顺着等待边能不能走回调用者。
  能走回 → **当场拒**，回 `is_error` 的 tool_result 说清「你等的那个正在等你」，
  让模型自己换个办法（决策 20 的哲学）。
- **在建立那一刻拒，不是等到卡住再救。** 卡住之后没有人有能力发现它——那正是上面
  说的「泵安静地返回」。

### 顺带承认一条代价

红线 10 原文点名的第二样东西——「横读会让『读所有兄弟』这种 O(n) 汇聚悄悄混进来」——
**确实被放开了**。诚实标注：活 agent 数被 `max_depth` / `max_children` 封顶
（默认 3/8，决策 32 起是启动参数）；快照路那半还是 tool_result 不是 derived，
**不会每次状态变化就重算**。这两条合起来让它可接受，不是它不存在。

## 二、发消息：两种送达时机，`Inbox` 私有槽 + 定点排空

用户 2026-08-18 拍的分档：

> agent 的 message 分两种，一种是这一轮结束之后、下一轮开启的；另外一种是直接加入
> 本轮 loop，加入 prompt，下一次发给 AI 请求带上。

| | `now`（本轮注入） | `next_turn`（下轮送达） |
|---|---|---|
| 送达点 | 收信人**下一次组装 provider 请求之前** | root **下一轮开始时** |
| 合法目标 | 本轮任意活 agent —— 后代 / 祖先 / **兄弟** | **只有 root** |
| 会不会唤醒 | 会（收信人已终态就把它拉回泵，§二「唤醒」） | 不会——它等的就是下一轮 |
| 典型用途 | 中途纠偏、兄弟交换中间结论 | 后台子干完了要给下一轮留话 |

### 为什么 `next_turn` 的目标只能是 root

**不是本决策加的限制，是既有架构掉出来的**：子 agent 不跨 turn，孤儿在 turn 收尾由
`despawn_child` 定点拆掉（ORCHESTRATION §二 / §四.4）。所以下一轮开始时活着的只有
root——投给别人等于投给一个下一轮不存在的收件箱。

发给不会活到那时候的目标 → **当场显式拒**，不是投完静默丢。

> 顺带一条值得记下的性质：**消息跨 turn，agent 不跨 turn。** 消息是 root 头上的槽位
> 状态，journal 带得走、崩溃恢复自动回来。所以 `next_turn` **不需要** ORCHESTRATION §六
> 延后的那套「跨 turn 后台 agent」机械（store 落地的 pending-slot 映射跨 `run_turn`
> 重挂、`turn_id`/undo 语义重写、per-child 取消）——一条都不需要。

### `next_turn` **会自己开一轮**（用户 2026-08-18 拍板）

留言不只是等着搭便车——**它自己就能把下一轮启动**，会话因此不需要人也能往下跑。

**这把今天的停机保证整个拆掉了，所以必须配一道新闸。** `TurnsUsed` 在 `begin_turn`
时重置为 0（`txn.rs:274`），而自开的每一轮都是**真的新一轮**，重置合法——于是
「每轮给自己留张条」可以永远跑，现有的闸一道都拦不住。

新闸：**会话级自驱动预算 `Slot::AutoTurnBudget`**（只写在 root 头上，`Private`）。

| 规则 | 为什么 |
|---|---|
| **只有真实用户输入把它加满** | 这是「人还在场」的唯一凭据。自开的轮次**只耗不加** |
| **`begin_turn` 不碰它** | 碰了就是把闸接回被它约束的那个循环里——等于没有闸 |
| 收尾时有 `NextTurn` 条目且预算 > 0 → 减一、开新轮 | |
| 预算见底 → **停下**，留言原地留在收件箱等真人 | 不是丢弃，也不是报错 |

**三条必须现在就答、答错都不报错的**：

1. **恢复之后不自动开轮。** 崩溃恢复完成时收件箱里若有 `NextTurn` 条目，
   **不启动**，等下一次真实驱动。否则「打开应用它自己就开始烧钱」，而且用户还没来得及
   看上一轮发生了什么。
2. **undo 不退还预算。** 撤销一轮自开的轮次，预算**不加回去**。钱已经烧掉了；
   退还等于交出一条「撤销 → 重跑 → 再撤销」的无限循环。
3. **面上必须分得出「这轮是它自己开的」**，并且能当场喊停。一个会自己往下跑的会话，
   用户失去的第一样东西就是「我知道现在在干什么」。CLI / web / 桌面三个面都要有。

### 不能直接往对方 `Messages` 上追加

对方可能正有一个 provider 请求在飞。那个请求带的是**旧**消息列表；回来的 assistant
消息会追加在注入的那条**后面**，于是历史里长出一段「答非所问」——下一轮模型读到的
就是错的。**这不报错。**

### 形状

新 primitive 槽 `Slot::Inbox`，站 `Visibility::Private`。**两种时机共用一个槽**，
条目自带时机标记：

```rust
struct InboxItem { from: AgentId, text: Arc<str>, when: Deliver }
enum Deliver { Now, NextTurn }
```

- **投递**是一条命令（红线 2），往目标 `Inbox` 尾部追加一条。
- **排空有两个定点，各只认自己那一档**：
  - `Now` → 收信人 `try_call_provider` **之前**排空；
  - `NextTurn` → root 的 `begin_turn` **之后、第一次组装请求之前**排空。
  - 两处都是命令，落 journal，恢复回放白拿。
- **一个槽两个标记，不是两个槽**：它们的落盘、恢复、undo、`Private` 语义逐字相同，
  差别只有「哪个定点来收」。拆两个槽就要把这四样各写两遍，而它们必须永远一致。
- `Private` 是刻意的：**发得进去 ≠ 读得出来**。A 能往 B 的 Inbox 投递，但 A 读不到 B 的
  Inbox（包括自己投的那条被没被消费）。发送方要知道结果就等对方回一条——跟人类一样。

`Now` 的三个方向都开（红线 10 改写之后没有理由再分）：父→后代（中途纠偏）、
子→祖先（中途汇报）、兄弟↔兄弟。**前提是「发给谁」那个 id 拿得到**，那是 207。
`NextTurn` 只有一个合法目标（root），理由见上。

### 唤醒：turn 内叫醒（**只对 `Now`**）

`NextTurn` 不涉及唤醒——它等的就是下一轮，没有人需要被拉起来。下面三档说的都是 `Now`：

1. **不叫醒**（Done 的 agent 收不到，`send` 报错）——「中途纠偏」还在，「让子 agent
   接着干」没了，价值砍一半。
2. **turn 内叫醒** ← **拍这个**。子仍在父的同一次 `run_turn` 内生死，于是 `turn_id` 继承、
   undo 连带子树、`Subtree` 局部绑定**全部一行不改**（ORCHESTRATION §二 的既有结论）。
3. **跨 turn 叫醒**（把一个已经死掉的子 agent 在下一轮复活）——ORCHESTRATION §六 延后的
   那件事，要重写 `turn_id` / undo 语义、要 store 落地的 pending-slot 映射跨 `run_turn`
   重挂。**不做，而且 `NextTurn` 已经把它想解决的问题解决了**：要跨轮传递的是**话**，
   不是**agent**。话留给 root，下一轮 root 想再 spawn 一个是它自己的事。

### 停机论证（本节最重要的一段）

今天泵停得下来（`runner.rs:291` 的 `calls.is_empty() && mcp_calls.is_empty()`），靠的是
**没有任何 agent 能把别人重新拉起来**：工作量只随 spawn 往下长，树被两道闸封顶，
所以有限。

加了唤醒边之后 A 能叫醒 B、B 能叫醒 A。兜底只剩每个 agent 自己的 `MaxTurns`
（`txn.rs:242`：`used >= max_turns` 就不给再调 provider）。总量 ≤ 活 agent 数 ×
`MaxTurns`——**仍然有限，但边界从「树的大小」变成「树的大小 × 每人的轮次预算」。**

> **这是本决策唯一会静默出错的地方。** `TurnsUsed` 在 `begin_turn` 时被重置为 0
> （`txn.rs:274`）。**唤醒绝不能走重置那条路**——写成重置，两个 agent 互相喊话就是
> 真无界。而它不报错、测试也不会红，只会把 token 预算烧到见底。205 的验收里有一条
> 专门钉它，别删。

**自驱动那一层的边界另算**，它是这个论证的第二层：轮次数 ≤ `AutoTurnBudget`
（只有真实用户输入才加满），每一轮内部再受上面那个「活 agent 数 × `MaxTurns`」约束。
**两层相乘就是一次用户输入之后的最坏开销**——这个数得写进启动参数的文档里，
因为部署方是靠它估账的。

三层闸各管一件事，谁都不能兼任：`max_depth`/`max_children` 管树多大、`MaxTurns`
管一轮里说多少话、`AutoTurnBudget` 管没人看着的时候能跑几轮。

## 三、自读与草稿纸

### `srv:agent/self`：自读零阻力，但结果会过期

`Private` 的含义是「**别的** agent 读不到」，不是「自己也读不到」——`visibility.rs:34`
专门澄清过：`Slot::TurnsUsed` 是 `Private`，本 agent 照读不误。所以自读**不碰任何红线**，
也不经 `peek_agent`（那是跨 agent 的口）。

给什么：`turns_used / max_turns`（`txn.rs:241`，撞顶就不给再调 provider）、
`retries_used / max_retries`、`depth` 与还能开几个子（`AgentLimits`，决策 32 起是
启动参数）、`tools_allowed` 的条数、上下文压过没有。模型今天对这些**完全瞎着**，
所以没法「快没轮次了就收敛输出」。

> **必须进 tool description 的诚实标注**：这一轮回「turns_used=3」，三轮之后模型读到的
> 还是那个 3，而它早过期了。**跟时间戳进 prompt 是同一类病**。措辞要明说「这是你调用
> 那一刻的数」，不许写成看起来永远成立的事实。

### `srv:agent/notes`：不给现有槽位开写口，给模型一个自己的槽位

用户原话是「改本 agent 状态」。逐字执行 = 给现有槽位开写口。而现有槽位一格一格数
过去，**没有一格是模型自己的**：

| 槽位 | 是谁的账 |
|---|---|
| `MaxTurns` / `MaxRetries` | **部署方的**——决策 32 刚把两道闸从「代码可配」搬到进程级启动参数，理由正是「这是部署方的决定」 |
| `ToolsAllowed` | **父给的**——spawn 的 `check_subset` 保证子只拿父的子集，单调收缩 |
| `SendPlan` / `Summaries` | **adapter 的**（压缩边界的记账） |
| `Status` | **别人要读的结论**（`Shared`） |

给这些开写口 = **让被约束者改自己的约束**：模型给自己加轮次、给自己发工具、改父要读
的结论。往模型手里塞 `MaxTurns`，是 M18 那个决定往反方向走一遍。

**所以给它一个自己的**：`Slot::Notes`，primitive、`Private`、
`BTreeMap<Arc<str>, Arc<str>>`（红线 11：它进 prompt，必须有序容器）。读写各一个 tool。

站 `Private` 而不是 `Shared`：模块文档的规矩是「开放要有理由，封闭不需要」——
横读全开之后这条规矩**更要紧了**，因为现在「开放」的默认后果是所有人都读得到。
草稿纸是自己写给自己的，别人要知道就问（`send`）。

买到的东西值得单说：它**白拿全套机制**——`/undo` 连带撤销、崩溃恢复自动带回、审计看得到
每一次改。写它是 `Aftermath::Nothing` / `Undoability::StateOnly`（M19 那套里最干净的
一格），undo 直接回滚状态，不需要任何钩子。**「模型的草稿纸自带 undo 和崩溃恢复」是
这套架构直接掉出来的，不是新造的机制。**

## 四、红线账（逐条过）

- **红线 2（禁 `store.set`，走命令层）**：投递、排空、写 notes 三样全是命令。
  `Session` 仍然不暴露 `store()`。
- **红线 3（primitive 的值全部可序列化）**：`Inbox` 是 `Vec<{from: AgentId, text}>`，
  `Notes` 是 `BTreeMap<Arc<str>, Arc<str>>`，都可序列化。
- **红线 6（在飞 effect 带 epoch、回写前校验）**：`send` 是当场回写的纯写命令，不产生
  在飞凭据。**但唤醒会**——被叫醒的 agent 新起的 provider 调用带的是**当前** epoch，
  undo / cancel bump epoch 之后它的回执照旧被 `step.rs` 那道门丢掉。不新造门。
- **红线 7（core 不做 IO）**：Inbox / Notes 都是纯状态，core 只记账。
- **红线 9（行数）**：`status_tool.rs` 今天 278 行，207 要改它必然顶破——**拆分是那次
  改动的一部分**，照 200 拆 `undo_hook.rs` 的先例。
- **红线 10**：**本决策改写它**（§一）。方向约束整条去掉，换成「**跨 agent 的边只许
  指向 primitive**」；`Visibility` 三态收成两态；`read_ancestor` / `read_descendant`
  留作带方向断言的薄封装。新判据由类型系统守着，比旧的更强。
- **红线 11（进 prompt 的逐字节确定）**：投递的正文进对方 `Messages` → 进 prompt。
  **不许带时间戳、随机 id**；`from` 是路径 id，确定。`Inbox` 是 `Vec` 有序，`Notes` 是
  `BTreeMap`；等待图也必须是有序容器（它进 `await` 的拒绝文本）。207 放开到全树之后
  `status` 的排序仍然自己 `sort_by`，不借 `live_agents` 的排序承诺
  （`status_tool.rs:169` 的既有理由不变）。
- **红线 12（core 无模型判断）**：五个工具全在宿主侧 dispatch 截获，照 spawn / status /
  collect 同款。core 不碰。
- **新的一条候选**（210 拍完再说要不要进 INVARIANTS）：**没有人看着的时候，会话能跑
  多久必须有个数**。`AutoTurnBudget` 是它的第一个落点。这条跟前面十二条不同——它防的
  不是错值，是账单。

## 五、明确不做（别在子 issue 里重开）

- **跨 turn 复活一个已死的子 agent**：见 §二「唤醒」第 3 档。跨轮传递的是话不是 agent。
- **给现有槽位开写口**：见 §三。要改 `MaxTurns` 请走启动参数（决策 32）。
- **跨 agent 读一个 derived**：§一 的新判据挡住它。真要，先回来改红线 10——
  它是「环不可能」这句话现在唯一的依据。
- **快照读 / 订阅 `Private` 槽位**：`Private` 的含义不变。
- **Inbox 的已读回执 / 投递确认**：`Private` 意味着发送方读不到对方 Inbox。要确认就等
  对方回一条。
- **等待环卡住之后的自动解救**：一律在**建立那一刻**拒（§一）。卡住之后没有人有能力
  发现它，造一套「检测死锁并挑一个牺牲者」的机制是在给一个已经能挡住的问题加机械。
- **`AutoTurnBudget` 的自动续期**（比如「按时间恢复」「按进展恢复」）：只有真实用户
  输入加满。任何自动续期都是把闸接回被它约束的那个循环。
