# 131 订正 vision 那句「不进任何持久化」

**里程碑** M14 · **依赖** 无 · **模型** sonnet · **独测** 否（纯文档） · **状态** 完成

## 目标

`agent-tools/src/vision_inspect.rs` 的模块文档现在写着图片字节

> 不落消息历史、不进 prompt、**不进任何持久化**

**最后半句不准确**，而且它准得刚好能把 M14 整个方案否掉——
下一个人读到它，会认为「图片进 IndexedDB」违反了一条既有承诺。

**无依赖，第一天就能开工。建议在 [128](128-idb-images-store.md) 之前落地**
——那条 issue 的实现 agent 会读到这句话。

## 事实

server 形态**本来就把字节落盘了**：`POST /uploads` 写 `<dir>/<id>`，
mime 写 `<dir>/<id>.mime`（`agent-server/src/http/uploads.rs`）。
CLI 形态更直接——图本来就是用户本机的文件。

所以那句话真正的意思、也是它真正在保护的东西，是：

> 不进**会话历史 / prompt / journal**

三种形态对这条都成立，而且成立的方式相同：模型只看到 `/uploads/<id>` 这个**链接
字符串**，字节只在工具执行的那一瞬间进内存、上传换成 `ms://` 引用之后就不再被引用。

## 做什么

1. 改 `vision_inspect.rs` 的模块文档。**把"不进任何持久化"换成准确的说法**，
   并补一句「字节在各形态下住哪」的对照——server 是上传目录，CLI 是用户本机文件，
   浏览器是 IndexedDB 的 `images` store。
2. 顺带核查同一句话有没有被抄到别处。至少要看：
   `docs/HOST-CAPABILITIES.md`、`docs/IMAGES.md`（已标废弃，但仍是决策档案）、
   `docs/issues/` 里 s5 重构那几条、`agent-server/src/http/uploads.rs` 的模块文档。
   **抄到哪就改到哪**——一句错的话留在别处，跟没改一样。
3. 在改后的文字里明确一件事：**这条承诺是关于"字节不进模型上下文"的，
   不是关于"字节不落盘"的**。两者被混为一谈正是这次订正的起因。

## 注意

- **只改措辞，不改行为。** 这条 issue 里 `.rs` 文件的改动应当全部在注释里
  ——`git diff` 除注释外零改动。
- 文档注释里一个错的理由比没有理由更糟，下一个人会照着它推。
  这条判断在 [099](099-send-plan.md) §「主会话复核修正的一处」里付过一次学费
