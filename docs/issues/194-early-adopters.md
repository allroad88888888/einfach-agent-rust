# 194 找 3–5 个真实嵌入用户

**里程碑** L · **依赖** [191](191-launch-post.md) · **谁做** **用户**（我做不了） · **估时** 持续 · **状态** 待开始

## 目标

让路线图**从猜测变成回应**。

CLAUDE.md 里已经写着这条原则：多租户、多副本 `RedisRegistry`、MCP 的 OAuth
「都等真实使用反馈再定，别提前猜」。这个 issue 就是去拿那个反馈。

021 那句话是同一个意思：**没被真实使用验证过的东西跟没写一样**。

## 为什么必须用户做

要找人聊。我可以准备材料，接触本身得你来。

## 做什么

1. 从首发（[191](191-launch-post.md)）的评论区和邮件里筛**真的在做嵌入**的人——
   不是「这个看起来很酷」，是「我正在给我们的后台加 agent」
2. 每个人问三件事：
   - 你的宿主是什么形态（浏览器 / 服务端 / 桌面）
   - 你的工具从哪来（自家接口 / MCP / 都有）
   - **你的第一个障碍是什么**（这一条最值钱）
3. 障碍逐条记进 issue，成为下一个里程碑的输入

## 验收

- 3–5 个真实对话记录（不是 star 数）
- 至少一条障碍**变成了 issue**
- 明确记下**没人提的东西**——如果 5 个人里没有一个人问多租户，
  那它就该继续排在后面。**这是本 issue 的隐藏价值**：它同时告诉你别做什么

## 注意

早期用户的意见容易被过度加权。**一个人提的不是需求，三个人提的才是。**
记录时把「谁提的」写清楚，别把一次对话写成「用户们希望」。
