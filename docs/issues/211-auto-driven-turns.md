# 211 自驱动轮次：`AutoTurnBudget` + 收尾自开 + 恢复不自开

**里程碑** M20 · **依赖** [206](206-send-tool-and-wakeup.md) · **模型** **opus** · **独测** ✅ · **状态** 待做

## 目标

决策 204 §二 的后半：**留言自己就能把下一轮启动**，会话因此不需要人也能往下跑。

**这是本仓第一次让会话在没有用户输入的情况下继续消耗 token。** 所以本 issue 一半是
「让它跑起来」，另一半是「让它停得下来、看得见、喊得停」——后一半才是重点。

## 做什么

### 1. `Slot::AutoTurnBudget`

新 primitive 槽，只写在 root 头上，`Visibility::Private`，`u32`。

| 规则 | 落点 |
|---|---|
| **只有真实用户输入把它加满** | `command/transitions/user_input.rs` 那条路，且**只有那条** |
| **`begin_turn` 不碰它** | `txn.rs:274` 附近那批重置**一个字都不加**——加了就是把闸接回被它约束的循环里 |
| 自开一轮 → 减一 | 减在**开轮之前**，不是之后 |
| 见底 → 停 | 留言原地留在收件箱，**不丢弃、不报错** |

默认值与 `AgentLimits` 同款：**部署方可配的启动参数**（`--max-auto-turns`，
`AGENT_MAX_AUTO_TURNS` 兜底），不是硬编码——照决策 32 的既有形状，恢复路径同样要
由宿主再说一遍（`recover` 的入参，照 [160](160-recover-limits-param.md)）。

### 2. 收尾自开

`runner.rs` 的 B 点，泵静止、root 落终态之后：

```
若 root 收件箱里有 NextTurn 条目：
    若 AutoTurnBudget == 0 → 停。条目原地留着，面上说清「还有 N 条留言，等你开口」
    否则 → 预算减一 → begin_turn → drain_next_turn → 继续跑
```

这个循环**在 `run_turn` 之外**（它每次都是一次完整的新 turn），不是把一次 `run_turn`
拉长——`turn_id` / undo / 孤儿收尾的语义因此全部照旧。

### 3. 恢复**不**自动开轮

崩溃恢复完成时，root 收件箱里若有 `NextTurn` 条目：**不启动**，等下一次真实驱动。

两条理由，都不能让步：**打开应用它自己就开始烧钱**；以及用户还没来得及看上一轮
发生了什么。恢复是「回到现场」，不是「接着跑」。

### 4. undo 不退还预算

撤销一轮自开的轮次，`AutoTurnBudget` **不加回去**。

钱已经烧掉了，退还等于交出一条「撤销 → 重跑 → 再撤销」的无限循环。
**这条要写进 `undo.rs` 的注释**——它看起来像个 bug，下一个人会想「顺手修一下」。

（实现上这意味着 `AutoTurnBudget` 的写入**不能**是普通的 journaled 状态回滚路径。
选一条：要么它不进 undo 的回滚集，要么每次自开都额外落一条不可回滚的记账。
**前者更简单，但要在 `Slot` 的文档里写死它是个例外**，否则「所有 primitive 都跟着
undo 走」这句话就不成立了。）

### 5. 三个面：看得见 + 喊得停

CLI / web / 桌面**都要**：

- 这一轮的来源是「自驱动」而不是用户，面上分得出来（不是只在日志里）；
- 剩余预算看得见；
- **能当场喊停**，且喊停之后剩下的留言**留在收件箱**（跟预算见底同一条路），
  不是丢掉。

## 验收

- **能自己往下跑**：预算 3 → 造一条自我续写的留言链 → 会话在**没有任何用户输入**的
  情况下连跑 3 轮。
- **停得下来**（本 issue 最硬的一条）：同样的自我续写链，预算耗尽后**停住**，
  留言还在收件箱里，进程既不 panic 也不空转。断言总轮次 == 预算初值。
- **`begin_turn` 不碰预算**：跑完 3 轮之后断言预算是 0，不是被某次 `begin_turn`
  重置成了 3。**写成重置这条必红**，而且它是这一波第二个不报错的静默错。
- **用户输入才加满**：预算耗尽 → 用户随便说句话 → 断言预算回到配置值，
  且那句话本身也照常处理。
- **恢复不自开**：留言在收件箱里时 `kill -9` → 恢复 → 断言**没有任何 provider 调用
  发生**、留言仍在、预算未变。
- **undo 不退还**：自开一轮 → `/undo` → 断言预算仍是减过的那个值。
- **喊停**：自驱动跑到第 2 轮时取消 → 停住，剩余留言**还在收件箱**，
  轮次结果不是把之前跑完的那几轮判成失败。
- **启动参数对齐**（决策 32 的既有规矩）：`--max-auto-turns` 配的数 =
  真正拦人的数 = `srv:agent/self` 回给模型看的数，三处同一组。
- `cargo test --workspace` 全绿 + `check-invariants --all` 过 + `build-wasm.sh` 绿 +
  `pnpm -r typecheck` 过。

## 注意

- **别让预算按时间或按「有进展」自动续期**（204 §五）。任何自动续期都是把闸接回
  被它约束的循环里，那就等于没有闸。
- **别把自开的轮次做成「一次超长的 `run_turn`」**。那会把 `turn_id` / undo 粒度 /
  孤儿收尾全部搅进来，而现在这三样一个字都不用改。
- **wasm 宿主同路要一起做，别后置。** 157 那次就是后置之后才发现要补做
  （见 `docs/issues/README.md` §M17 那段）。浏览器里一个会自己跑的会话，
  「看得见 + 喊得停」比在 CLI 上更要紧——那儿没有 Ctrl-C。
- 这条与 [206](206-send-tool-and-wakeup.md) §4 的孤儿收尾**共用 B 点**。两处都改
  同一段代码，**先做 206 再做本条**，别并行。
