# 150 决策：扩展 derived 公式与状态谓词触发的形状

**里程碑** M16 后半 · **依赖** [149](149-extension-dogfood.md)（拿它的手感当输入） · **模型** **opus** · **独测** 决策类 · **状态** 完成（2026-08-12 拍板 = 决策 30）

## 要决什么

扩展系统的「必杀器」层（2026-08-12 讨论定的方向，实施形状未定）：

1. **扩展定义 derived**：ExtensionPack 能不能带「公式」——对状态图的纯派生
   读，依赖自动追踪、变了才重算、undo/恢复后自动一致。
2. **状态谓词触发**：「当某 derived 翻真时调我的 hook」——把 CallTiming 从
   两个内置时机（SessionStart/TurnEnd）泛化成扩展自定义的状态条件。

## 讨论已收敛的判据（重开讨论先读这段）

- **纯度靠什么**：扩展是受信 Rust（决策 29），纪律 = 与自有代码同一套
  （红线 1 + check-invariants 扫描面**要扩到扩展模块**——这是本决策要落的
  硬项之一）。wasm 纯函数沙箱是「将来接不受信代码」的备选，本轮不建。
- **触发不许碰 prompt**：决策 21 否决自动激活的理由原封不动——触发只能发
  hook，hook 的效果走 command/工具面（journaled、可见、可撤），永不直接
  改组料。
- **判定时点**：只在 flushPending 之后的稳定态上判定，扩展永远看不到
  传播中途的半更新世界。
- **回写过闸**：hook 若引发异步回写，照红线 6 带 epoch。

## 拍板记录（2026-08-12，= 决策 30，全文在 ROADMAP §一）

比预设的三个大问题小一圈——149 的手感把问题削没了两个半：

1. hook 没有独立概念：就是 `TurnEnd` 时机的工具，外围工具决定一切。
2. `TimedRun` 加只读 `&Session`（唯一的实现刀，落 153）；「hook 不写状态」
   从纪律变成签名。
3. 扩展**不设** derived 注册面：真实需求单上全是「被问才算」——截获工具拿着
   Session 被调时现算，工具体内自便。core 自己的 derived 引擎照旧。
4. 谓词触发（反应式层）不做：它服务的用户不存在，且「没人喊自己动」正是
   决策 21 否决自动触发时警惕的形状。讨论全文记档防重开。

151/152 随之撤销。预写的判据段（纯度/不碰 prompt/稳定态/epoch）保留在上文——
若将来反应式层因真实需求复活，从那里接着读。
