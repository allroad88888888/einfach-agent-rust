## 二、真机 dogfood（真 provider，不是 mock）

照 049 / 054 的规矩。七条，每条都要能在终端上看见结果：

1. **兄弟对话**：父 spawn A、B → A `send` 给 B 一个中间结论 → B 用上它 →
   两边都答对。**这是「横读开了」的行为证据。**
1b. **兄弟互等**（212）：A `await` 兄弟 B → B 干完 → A 继续。
   再让 B 反向 `await` A → **B 当场拿到错误、两边都没卡住、这一轮正常结束**。
1c. **自驱动**（211，本波最该亲眼看的一条）：留言链 + `--max-auto-turns 3` →
   **人不碰键盘，会话自己跑三轮然后停住**；面上从头到尾看得出「这轮是它自己开的」、
   剩几格预算；中途按一次停，剩余留言还在。再 `kill -9` 重启 → **它不自己跑**。
2. **中途纠偏**（`when="now"`）：父 spawn 一个后台子 → `status` 看到它在往错方向走 →
   `send` 一条「改做 X」→ 子改了 → `collect` 拿到改过的结果。
2b. **下轮留言**（`when="next_turn"`）：后台子在轮末给 root 留一条 → **这一轮照常结束、
   不被延长、面上不告警** → 下一轮用户随便说句话，模型答得出那条留言的内容。
   `kill -9` 插在两轮之间再走一遍——留言得活过重启。
3. **草稿纸 + undo**（209 的卖点，要**演出来**）：模型写几条 notes → `/undo` →
   **条目真的没了**；再 `kill -9` + 恢复 → 条目**真的回来了**。
4. **自读收敛**：把 `max_turns` 调到很小 → 模型调 `self` 看到快没轮次 →
   **主动收敛输出**而不是被闸硬切断。

第 4 条**可能不过**——模型会不会真的据此收敛是它自己的事，不是代码的事。
不过就如实记「模型没有据此改变行为」，**别改判据凑绿**，也别因此加提示词去哄它。
这一条的价值在于知道答案，不在于答案是绿的。

### 真机独有的四个 bug（测试全绿的情况下）

1. **CLI 宿主根本没接 `report_recovered_mail`**。`kill -9` 之后重启，留言好端端在
   收件箱里，终端上**一个字都没有**。server 与浏览器两个宿主都接了，唯独 CLI 漏了
   ——所有测试都**直接调**那个函数，没有一条走 CLI 的 `main`。「看得见」这条承诺
   在人真正用的那个宿主上是空的。
2. **被叫醒的后台子，`collect` 领回的是叫醒之前那份答案**。214 与 053 在交接处
   没人测过：后台子落终态时被划出收割名单，醒来后再落终态时不再被收割。
3. **第一版修法在真机上又错了一次**：光把它挪回收割名单不够——`Event::Wake` 还在
   队列里没被 `step`，它此刻仍是终态，下一圈收割立刻把旧答案打回去。加了「醒来
   标记」才对。**这一条钉成了确定性测试**（`wake_collect_after_wake.rs`），
   因为真机复现要靠模型配合，而同一份提示词三次里两次跑偏。
4. **M20 五个工具在终端上全印着 `reversibility=Irreversible`**，而 TOOLS.md 写着
   它们全在 `Nothing` 那一格。行为上没差别（截获路从不 `mark_no_undo`），
   但 202 的教训就是「印给人看的那个字要么是真的，要么别印」。

外加两处文案在终端上是坏的：`[自驱动]` 那行里有二十来个空格（`\` 续行被 rustfmt
折成一行留下的），以及 `**...**` 的 markdown 星号——终端不渲染，用户看到的就是星号。

### 三个行为观察（不是 bug，但下次设计要知道）

- **`background=true` + root 立刻收尾 = 子的 `send` 根本来不及发**。第一次跑 1c
  就撞上：子还在飞，root 答完了，轮末 `despawn_child` 把它拆了。052 的正确行为，
  但**模型会踩**——它不知道自己得等。
- **模型会把多步任务拆成几轮**，于是后台子在轮末被回收，第三步 `send` 撞
  「不在活 agent 里」。拒绝文案说清了原因和下一步（这一点是好的）；要一轮做完
  得在提示词里明写「中间不要停下来回答我」。
- **模型自己识破了无限递归并停下**：1c 的留言链跑到第二轮时它说「这没有终止条件，
  我停在这里」。**这正是第 4 条想看的那种自主收敛**，只是发生在别的地方。

### 第 4 条为什么只做了一半，以及要补什么

`--max-turns` 今天**只有 root 设得了、而且没有启动参数**（`Session::set_max_turns`
是 API，CLI 没暴露；`ChildConfig` 也没有这个字段，子 agent 恒是默认 32）。所以
「把一轮最多说几次话调到很小，看模型会不会主动收尾」在真机上摆不出来。

214 的独立测试 agent 也报过同一个缺口（它写「撞顶不唤醒」时够不着子 agent 的
`max_turns`）。**两处独立撞到同一个洞，说明该补一个 `--max-turns` 启动参数**，
跟 `--max-agent-depth`/`--max-children`/`--max-auto-turns` 同一档。留给 M20 之后
的一条小 issue，不塞进 213。

### 1b 补跑（212 落地之后，2026-08-18）

**正向过了**：root 一次回复里并行开两个后台子，`root/a2` 的 task 是「用
`srv:agent/await` 等你的兄弟 `root/a1`」——它真的挂住、A 干完之后收敛，返回

> `root/a1 到了（它收场（不管成没成））。**这里不给正文**——要它的回答用 srv:agent/collect 领。`

**这是「兄弟能互相等」的行为证据**，走的正是那条全系统第一条跨 agent 依赖边。

**反向（互等被拒）真机上摆不出来**，原因是模型的轮次结构而不是代码：要摆出环，
得让 A 先建立「A 等 B」、再让 B 去 `await` A，而这要求 root 在**同一轮**里连着做
两步。实测三次里模型两次把两步拆成两轮，于是后台子在第一轮末就被回收了，第二步
撞的是 `NotLive` 那条（「等一个不活的 → 当场 `is_error`，不是永远挂着」——那本身
也是 212 的一条验收，如实算过）。

**所以环那条留给独立测试 agent 用确定性夹具钉**（212 §验收 第 2/3 条）。这不是
降级：查环是一条**判据**，判据该在测试里钉死；真机要证的是「这条判据在真模型面前
不误伤」，而那一点由正向那半边证到了。

同一个原因也解释了前面几条为什么反复重跑：**模型每次的轮次切分都不一样**，
凡是「必须在一轮里连着做完 N 步」的场景，真机上都不稳。下次设计 dogfood 剧本时，
把每一步拆成独立的一轮（用户输入驱动），比在提示词里喊「不要停下来」可靠得多。

## 浏览器 demo 那条：**做了**（2026-08-18）

一开始判成「产品决策，等人拍板」，但 §三 的原文点名了「**别假定 wasm 白拿**，
157 那次就是后置之后才发现要补做」——那是计划的一部分，不是一个开放问题。
所以照做了，把代价写清楚而不是卡在问句上。下面这一段是当时的判断，留着记录
为什么它看起来像个决策：

`agent-wasm`（Pages 上那个没有服务端进程的浏览器宿主）的工具表是
`ToolTable::empty()` 起步——`crates/agent-wasm/src/tools.rs` 的模块文档写着
「**每一档 `with_*` 都是一次独立授权**——浏览器宿主目前一档都不开」，
连 `spawn`/`status`/`collect` 都没有。所以 M20 这一族在那儿看不见，不是漏接。

要让它看得见，得先在浏览器里**开 spawn**——那意味着页面上一次对话可以自己长出
一棵 agent 树，每个节点都花使用者自己填的那把 key。**这跟 server 形态不同**：
那边是部署方决定开哪几档、部署方付账。所以这一条我不替产品拍板。

（`packages/web` 那个**接 server** 的前端不受影响：它走 `ToolTableSpec::Full`，
M20 五个工具都已经在表里，事件（`auto_turn_started`/`auto_turn_held`/
`unread_messages`）也都接到了 `render/notice.ts`。）

### 实际怎么做的

`browser_tool_table` 上开了整族七档（spawn/status/collect/send/self/notes/await），
判据在 `tools.rs` 的模块文档里写成一条**可以照着判下一个工具的规则**：

> 分界线是「**这个工具在浏览器里执行得了吗**」。shell/fs 要文件系统，执行不了，
> 声明了就是骗模型；子 agent 那一族的执行体就在本进程里（dispatch 截获，
> 一行 IO 都没有），wasm 上跟 native 上跑的是同一段代码。

**代价如实写在那段注释里**：页面上一次对话可以自己长出一棵 agent 树，每个节点都花
使用者自己填的那把 key；`--max-auto-turns` 的默认值（3）在这里也生效。两条兜底
都在：`AgentLimits` 三道闸照常拦人；页面的 **Cancel 按钮接的是同一个取消标志**
（`try_one_auto_turn_async` 在开每一轮之前先看它），而自驱动的循环就跑在
`turn::run` 里，所以那个按钮在自驱动期间是**亮着的**。浏览器里没有 Ctrl-C，
那是唯一的出口。
