# 184 文章：我删掉了自己刚写完的 skill 激活子系统

**里程碑** L · **依赖** [165](165-launch-positioning-decision.md) · **模型** **opus** · **估时** 20min · **状态** 初稿完成（2026-08-13）

## 目标

讲决策 21 → 决策 27 的推翻过程。

「我推翻了自己」这类内容传播力强，因为它**反向证明了严肃性**——愿意删掉自己刚写完的
东西的人，说别的话也更可信。而且它顺带把架构讲清楚了，读者不觉得在被推销。

## 素材

- 决策 21（原案）与决策 27（取代案）的完整理由，在 [../ROADMAP.md](../ROADMAP.md) §一
- [141](141-remove-activation-subsystem.md)：整条删除的实做

- 038 探针：当初为三家测出的「注入分策」（DeepSeek 段尾 91%）——**那套现在整个不需要了**

## 写什么

标题方向：*I built a skill-activation subsystem, measured it, and deleted all of it*

叙事骨架：

1. **问题**：能力目录很大，全塞进 prompt 每轮都全价
2. **第一版**：模型经工具激活 skill → 正文注入 system 段尾部。为此专门测了三家的
   注入位置偏好，还得出了「DeepSeek 放段尾命中 91%」这种精细结论
3. **转折**：业内收敛到另一条路（正文走 tool result 进消息尾）。
   **消息尾追加正是 prompt 缓存本来就为之设计的方向**——而中途插 system 段是在跟缓存对着干
4. **实测**：换过去之后十轮 97.5%–99.8%，含发生读取的轮
5. **删除**：`skills_active` / activate / deactivate / 注入路径整条删掉。
   038 那套精细的分家策略随之报废——**测得越细，越舍不得删，这正是要警惕的地方**
6. **留下的疤**：`Slot::SkillsActive` 只能留壳，因为老会话的 journal 里真有那些 entry
   ——这一段很值钱，它说明**「有账本」是要付代价的**，而付了代价才换到崩溃恢复和审计回放

## 验收

- 第 6 点必须写到——没有它这篇就是一篇普通的「我重构了」，有了它才是账本系统的现身说法
- 数字与 [143](143-m15-dogfood.md) 一致
- 不贬低第一版的做法（它当时是有依据的），**要点是「测量胜过设计」不是「我以前很蠢」**

## 实做记录（2026-08-13）

**初稿在 `scratchpad/184-draft-en.md`。**

### 标题里放了行数

*I built a skill-activation subsystem, measured it, and deleted 1,945 lines of it*
——[141](141-remove-activation-subsystem.md) 的 `git diff --stat` 原数（65 文件、
+607/−2552、净减 1945 行、8 个整文件、34 个测试）。**具体数字比「大量代码」有说服力
一个量级**，而且它是可核对的。

### 立意换了一次，换出了这篇的价值

原计划的骨架是「问题 → 第一版 → 转折 → 实测 → 删除 → 留下的疤」，一条时间线。
写到中段发现真正的论点不在时间线上，而在两次测量的**对比**里：

- **让它看起来很好的那次测量**（038）：DeepSeek 上「插消息」归零 vs
  「改 system 段尾」保住 91%。这是**好工程**——真实差异、可复现、按 adapter 层的分工
  正确落位。
- **杀死它的那次测量**（143）：换成工具结果通道，十轮 13 跳 97.5%–99.8%，
  含 3 个 read 跳，零条低于 0.9。

**第一次测量测的是「怎么把不该做的事做得不那么糟」。** 91% 那个我最得意的发现，
描述的是一条本不该存在的代码路径的最优形态。

于是全文的论点定成：**测量的精确度完全不能说明被测的东西该不该存在。**
而具体的陷阱是——**调查一件事会让它显得更必要**：跑完三家探针、找出真实的不对称、
落成 per-provider 策略之后，那个子系统变成了我在整个代码库里最懂的东西，
而那恰恰是最该警惕的信号。

结尾那句是这篇的落点：*「这东西该存在吗」通常比「我怎么把它做得更好」更便宜，
而我把顺序搞反了。*

### 「删不掉的那部分」写成了正面论证，不是遗憾

`Slot::SkillsActive` 留壳（老会话 journal 里真有 activate entry，删变体 =
老快照反序列化直接断）。这一段原本容易写成「代价」，改成了：

> 这套系统的核心主张是「所有状态活在一张原子图 + 一份命令日志里，所以 undo /
> redo / 崩溃恢复 / 审计回放是同一套机制」。**这个性质的账单就是：你没法悄悄
> 下架一个状态形状。** 账本是真的，它就装着真的历史，而真的历史会约束你。
> 一个假 undo 的系统（删掉几个 UI 状态就完事）反而能干净地删掉这个变体——
> 因为它本来就没在记录任何东西。
>
> **那个残留的枚举变体不是债，是收据。**

这一段是全文最值钱的地方，也正是本 issue 验收第一条要的东西。
