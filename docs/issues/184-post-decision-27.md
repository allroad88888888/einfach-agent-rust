# 184 文章：我删掉了自己刚写完的 skill 激活子系统

**里程碑** L · **依赖** [165](165-launch-positioning-decision.md) · **模型** **opus** · **估时** 20min · **状态** 待开始

## 目标

讲决策 21 → 决策 27 的推翻过程。

「我推翻了自己」这类内容传播力强，因为它**反向证明了严肃性**——愿意删掉自己刚写完的
东西的人，说别的话也更可信。而且它顺带把架构讲清楚了，读者不觉得在被推销。

## 素材

- 决策 21（原案）与决策 27（取代案）的完整理由，在 [../ROADMAP.md](../ROADMAP.md) §一
- [141](141-remove-activation-subsystem.md)：整条删除的实做
- [143](143-m15-dogfood.md)：十轮 97.5%–99.8% 的实测
- 038 探针：当初为三家测出的「注入分策」（DeepSeek 段尾 91%）——**那套现在整个不需要了**

## 写什么

标题方向：*I built a skill-activation subsystem, measured it, and deleted all of it*

叙事骨架：

1. **问题**：能力目录很大，全塞进 prompt 每轮都全价
2. **第一版**：模型经工具激活 skill → 正文注入 system 段尾部。为此专门测了三家的
   注入位置偏好，还得出了「DeepSeek 放段尾命中 91%」这种精细结论
3. **转折**：业内收敛到另一条路（正文走 tool result 进消息尾）。
   **消息尾追加正是 prompt 缓存本来就为之设计的方向**——而中途插 system 段是在跟缓存对着干
4. **实测**：换过去之后十轮 97.5%–99.8%，含发生读取的轮
5. **删除**：`skills_active` / activate / deactivate / 注入路径整条删掉。
   038 那套精细的分家策略随之报废——**测得越细，越舍不得删，这正是要警惕的地方**
6. **留下的疤**：`Slot::SkillsActive` 只能留壳，因为老会话的 journal 里真有那些 entry
   ——这一段很值钱，它说明**「有账本」是要付代价的**，而付了代价才换到崩溃恢复和审计回放

## 验收

- 第 6 点必须写到——没有它这篇就是一篇普通的「我重构了」，有了它才是账本系统的现身说法
- 数字与 [143](143-m15-dogfood.md) 一致
- 不贬低第一版的做法（它当时是有依据的），**要点是「测量胜过设计」不是「我以前很蠢」**
