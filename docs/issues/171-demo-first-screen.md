# 171 demo 页首屏改造：从开发页变成展示页

**里程碑** L · **依赖** [170](170-pages-workflow.md) · **模型** sonnet · **独测** — · **估时** 20min · **状态** 完成（2026-08-13）

## 目标

`www/index.html` 今天是**开发调试页**（M13/M14 期间自己用的）。挂到公开 URL 上之后，
它是绝大多数人对这个项目的**第一印象，也常常是唯一一次印象**。

一个陌生人落到那个页面，30 秒内必须回答三个问题：**这是什么** / **我的 key 安不安全** /
**我该点哪里**。答不上来就关掉了。

## 现状

- 页面直接是操作界面，没有任何自我介绍。
- key 输入框没有解释——**这是最大的流失点**：让人在一个陌生网页里贴 API key，
  不解释清楚没人会做。而这里的真相恰恰是最好的卖点：**key 不出浏览器**。

## 做什么

1. 首屏加一段简介（英文，[165](165-launch-positioning-decision.md) L1）：一句话定位 +
   「no server — this page **is** the agent runtime, compiled to wasm」。
2. **key 说明**（这段值得单独写好）：
   - your key stays in this tab, goes straight to the provider
   - 页面**没有后端可以泄露到**——这不是承诺，是架构事实
   - 指一下怎么核实：打开 Network 面板，只有对 provider 的请求
   - 支持哪几家 + 各自拿 key 的链接
3. 三个钩子做成**可点的引导**（[165](165-launch-positioning-decision.md) 那三条），
   最重要的是 `/undo` ——给一句预置的话术让人照着试。
4. 加一行 GitHub 回链（demo 的目的是把人送回仓库）。

## 验收

- 一个没读过 README 的人，只看首屏能说出「这是什么」和「key 去哪了」
- 页面在窄屏（手机）不塌——很多人是从手机点开社交媒体链接的
- 改动**只碰 `index.html` 的展示层**，不动 `page-tools.js` 等执行路径
  （[169](169-wasm-artifact-recheck.md) 验过的东西不要在这一步动）
- 改完重新验一遍 [169](169-wasm-artifact-recheck.md) 的「跑通一轮」

## 注意

别为了好看引外部 CSS/字体 CDN——多一个外部依赖就多一个加载失败点，
而且会破坏「这个页面除了 provider 不连任何东西」这个卖点。**内联样式**。

## 实做记录（2026-08-13）

### 改了什么

1. **`<title>`** 从 `agent-wasm 浏览器宿主（issue 114c）` 换成
   `einfach-agent — an agent runtime running entirely in your browser`。
   标题是搜索结果和分享卡片上的那一行，内部 issue 号对外没有意义。
2. **favicon**：内联 SVG data URI（`↺`，一号钩子的符号）。
   [169](169-wasm-artifact-recheck.md) 查出的唯一 console error 是 `favicon.ico` 404
   ——**现在控制台零 error**。用 data URI 而不是外链文件是有理由的：这个页面的卖点
   之一就是「除了 provider 不连任何东西」，多一个外部请求就多一个能打脸的地方。
3. **首屏英文化**（[165](165-launch-positioning-decision.md) L1）：一句话定位
   + key 安全 + GitHub 回链。
4. **key 说明**写成最强的那个形状：*This isn't a promise, it's an architectural fact:
   there is no backend to leak it to.* 并给了**核实方法**（DevTools → Network），
   外加三家拿 key 的链接。让人在陌生网页里贴 API key 是最大的流失点，
   而这里的真相恰恰是最好的卖点。
5. **四步口令实验**写成可照抄的话术（[196](196-wasm-expose-undo.md) 真机跑通的那一套）。
6. **七处访客必须碰的控件双语化**：api_key / 建宿主 / 会话 id / 打开会话 / 输入框 /
   发送 / 撤销一轮 / 重做。
7. 窄屏 media query（≤34rem）：标签占整行，输入框不被挤成一条缝。

### 中途返工一次（值得记）

第一版把「Try this」四步和「两件值得试的事」全放在**首屏顶部**。截图一看
——**hero 占满整个视口，api_key 输入框被挤到折叠线以下**。这就等于没回答
「我该点哪里」，而那是首屏三个问题里最要命的一个。

读者是先连上再玩，不是先读完再连。

## 拆不拆的决定（2026-08-13）

上面留的两条尾巴都挂在同一个问题上：「验收页与对外 demo 要不要拆成两个」。
[193](193-embed-example-build.md) 也把「两个 demo 语言策略应该统一」挂在了这条上。
定了：**不拆。**

### 先推翻了「被挡住」这个前提

我一直把这条记成「被验收夹具挡着」。**去查了一下，这个前提是错的**：
`grep -rn index.html scripts/ crates/agent-wasm/{src,tests}` 只有五处**注释**提及，
**没有任何自动断言绑在页面文案上**。所谓「验收夹具」是一个人手动驱动的页面。

所以真正要保住的从来不是「测试别挂」，是**那些带 issue 号的标签对做验收的人的语义**。
这是个弱得多的约束，而弱约束有更便宜的解法。

**「被 X 挡住」是一个会自我延续的判断**——记下来之后就没人再去验它了。
这条挂了整整一轮，而验它花了两分钟。

### 做法：不拆页，把验收控件收进折叠块

- 访客看得见的一律英文（legend / 按钮 / placeholder / **以及 14 处 JS 状态串**——
  状态串跟按钮一样在屏幕上，漏掉它们等于没做）
- 三个**只对验收人有意义**的控件（`context_window` 的 M12 五档、121 工具回调、
  122 反向锁）收进 `<details>「Acceptance controls」`，**中文与 issue 号逐字原样保留**
  ——翻译或简化它们就等于把验收步骤改掉了
- `html lang` → `en`

**为什么不拆**：两个页面就是两份要同步维护的东西，而这里真正的诉求只是
「访客的视线里不要有它」。一个 `<details>` 就够，且**验收人打开一次看到的
是与之前逐字相同的东西**。

顺带 `roles.html` 一直是全英文 + `.en` 装中文次要标签，index 改完与它同构
——[193](193-embed-example-build.md) 那条「语言策略应该统一」自然满足。

### 真机复验（改完必须重跑，171 验收原文就这么要求的）

| | 结果 |
|---|---|
| 建宿主 → 开会话 | ✅ `connected — … key=35 chars` / `replayed 0 message(s)` |
| 真实一轮 × 2（记口令 → 问回） | ✅ 模型答出 `quokka-88` |
| 撤销两轮 | ✅ `undid 3 change(s) (turn 3)` / `undid 2 change(s) (turn 2)`，历史清零 |
| **中性追问**（句中不出现 undo） | ✅ *"No — in our conversation so far, you haven't told me a passphrase."* |
| 控制台 error | ✅ 0 |
| JS 取用的 26 个 id | ✅ 一个没丢（英文化最容易毁的就是这个，所以先脚本核了一遍） |
| 三门禁 | ✅ `check-invariants --all` / `build-wasm.sh` / `cargo test --workspace` 退出码全 0 |

### 中途抓到两个东西

**一、我自己改出来的一处半截字符串。** 替换 `key=${…} 字` → `chars` 时，
原串后面还有 `符，识图 key=… 字符`，于是拼成了 `key=35 chars符，识图 key=0 字符`。
**是真机第一次连接时当场看见的**——纯静态检查不会报，因为它语法完全合法。
修完顺手扫了一遍「英文里夹中文残片」的行，确认只有这一处。

**二、一个 171 当初没验到的真问题（不是这次改出来的）。**
390×844（iPhone）上量：`api_key` 输入框顶边在 **939px**，视口 844
——**它一直在折叠线以下**。171 的验收写的是「窄屏不塌：零横向溢出」，
那条是真的过了，但它没验「能操作的东西在不在屏幕里」——**而那正是 171 自己
在返工记录里立的判据**。写下判据和把判据变成验收项，是两件事。

本次改动把它从 939 提到 888（少了一行），仍不够。补了一条只在 ≤34rem 生效的
`.zh { display: none }`：页面已是 `lang=en`、面向英文读者，中文读者有 `README.zh-CN`，
而在手机上那段中文摘要挤掉的恰好是「我该点哪里」那个答案。
**939 → 888 → 792**，进首屏了。桌面宽度下中文段仍在（验过）。
