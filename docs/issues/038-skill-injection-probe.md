# 038 探针：消息级 system 注入的三家实测

**里程碑** M5 · **依赖** 无 · **模型** sonnet · **独立测试 agent** 探针类不派 · **状态** 待办

## 目标

回答一个决定 039 设计的问题：**会话中途追加一条 `role:"system"` 的消息**，
三家（deepseek-v4-pro / kimi-k3 / glm-5.2）——

1. 收不收（HTTP 层不 4xx）？
2. 模型**听不听**（注入的指令真的改变后续行为）？
3. **保不保前缀**（追加后下一轮的 `cached_tokens` 是否仍按严格延长命中）？

PROVIDERS.md 只测过 Kimi 的消息级 **tools**（零缓存代价）；消息级 **system**
是空白。039 的注入策略押在这上面，按仓规：不猜，测。

## 做什么

`probes/api` 加一组实验（照既有 exp/ 结构）：每家跑同一脚本——

- 轮 1：普通对话建立前缀基线（记 usage）
- 轮 2：历史尾部插入一条 `{"role":"system","content":"<明显改变行为的指令，
  如：从现在起每次回答末尾加【标记X】>"}` + 新用户消息 → 记：HTTP 状态、
  回答是否带标记（听没听）、`cached_tokens`（前缀保没保）
- 轮 3：再普通一轮 → 验证注入后的新前缀继续命中
- 对照组：同内容改为**并进顶层 system** 再发 → 量化「注入 vs 重build」的
  cached 差值（039 拿这个数字算 Adjustment 的 est_cost_multiple）

结论写进 `probes/PROVIDERS.md` 新小节（该文档是三家差异唯一档案，别散），
原始 usage 落 `probes/results/`。**探针照旧不打印 key**。

## 验收

三家 × 四问（收/听/前缀/对照差值）的实测表进 PROVIDERS.md；花费 ≤ ¥2 量级；
探针可重跑（时间戳 nonce 冷启动）。

## 注意

「收」≠「听」：有的家可能 200 但把中途 system 当普通文本弱化——所以标记测试
必须是行为级断言，不是状态码断言。跑三次取多数，防单次抽样噪声。
