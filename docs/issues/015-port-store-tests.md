# 015 移植上游的行为测试

**里程碑** M2 · **依赖** 007 · **模型** haiku · **独立测试 agent** 否 · **状态** 完成

## 目标

把 `einfach-core` 的测试搬过来跑绿。**这是 007 那次移植正确性的唯一证据。**

## 为什么单独一个 issue

007 只保证「编译通过」。编译通过的移植可以完全跑不对——尤其是 pending 队列的
glitch-free 传播和 256 深度预算那种逻辑，改错了不会有类型错误。

分开还有一个好处：007 出问题时能确定是移植错了；这里出问题时能确定是行为变了。

## 做什么

上游 `tests/` 与各文件内联的 `#[cfg(test)]` 全部搬过来，值类型换成 `AgentValue`。

**Excel 专属的测试逐个决定**：删还是改。删的要在本 issue 里写明为什么——
「因为删了 `ArrayData`」是合理的，「因为跑不过」不是。

## 验收

- `cargo test -p agent-store` 全绿
- 删掉的测试有逐条说明
- 覆盖到这几条上游的核心行为：同步可重入（listener 里再写）、
  glitch-free 传播（一次 batch 里下游只重算一次）、循环依赖检测、
  256 深度预算下的深链求值

## 注意

跑不过时**先怀疑移植，别改测试**。测试是上游沉淀下来的行为规格，改它等于悄悄改语义。
真判定某条不适用了，写清楚理由再删。
