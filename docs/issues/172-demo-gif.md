## 目标

README 第一屏要一张会动的图。文字说「undo 是真的」没人信，**演一遍就不用信了**。

## 拍什么（这是本 issue 的全部难点）

**不要拍「跟 agent 聊天」**——那个所有人都见过，零信息量。拍 [143](143-m15-dogfood.md)
的口令实验，因为它是**别人家演不了**的：

```
1. 告诉 agent 一个口令        "记住口令：raccoon-seven"
2. 问它，它答得出              → "raccoon-seven"
3. /undo
4. 再问它                      → "我的上下文里不存在任何口令信息"
```

第 4 步是全部价值所在：**别人家的 undo 只删 UI，模型还记得**。这个对比在 15 秒内讲完，
而且看的人自己就能推出「哦，这东西的状态是真账本」——比任何一段架构描述都快。

**备选（如果 undo 那条拍得不够快）**：`kill -9` 之后接着聊。更硬，但要拍终端，
比页面内演示多一层解释成本。

**录之前先读 [169](169-wasm-artifact-recheck.md) 实做记录里那个坑**：问句里出现「undo」
「刷新」这类词会把答案喂给模型，录出来的是假的。中性问「口令是什么」，
且一旦模型答歪就换会话重录——脏历史上补录不回来。

## 做什么

1. 定分辨率与时长：**≤ 15 秒、≤ 5MB**，GitHub README 里超过这个尺寸加载体验就崩了。
2. 录制（浏览器窗口，不要整屏——桌面杂物会分散注意力）。
3. 关键帧加字幕标注，尤其第 4 步那句回答要能看清。
4. 落 `docs/assets/`（或 `.github/assets/`），**进仓库**——外链图床会挂。

## 验收

- 静音、无字幕也能看懂（社交媒体上默认静音，且很多人只扫一眼）
- 文件 ≤ 5MB，在 GitHub README 里加载不卡
- 第 4 步的模型回答**清晰可读**——那一句是整张图的全部意义
- 内容是真实录制，**没有剪辑掉失败的尝试**（要是它没答对，那说明有 bug，去修 bug）

## 退路

[196](196-wasm-expose-undo.md) 若来不及，改用 **CLI 录**（`/undo` 在 CLI 上是完整的，027）。

一张终端 GIF 是「他说他能」，一个可点的 demo 是「我自己试了」。
