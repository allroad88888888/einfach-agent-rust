The host decides what the agent can do

Same wasm binary, same model, same prompt — two roles, two different tool tables. ← back to the main demo · source

Why this can't be hard-coded. The tool table isn't a property of the build — it's supplied by the host when it creates the conversation. Here a viewer gets one read-only tool and an operator additionally gets a refund tool. One deployment, one agent, and the capability surface changes per caller. There is no version of this that a fixed tool list in the Rust core can express.

Two more things fall out of it, and both are visible here:

  • Refund is declared irreversible. Ask the operator to refund something, then hit undo — it stops and names the tool that blocked it, instead of silently rolling back a payment that already left. The money is in this page's memory; the ledger can't reach it, which is exactly why the barrier exists.
  • The role is journaled with the session. Reload the page and reopen a viewer session: it comes back as a viewer, with the tool table it had at the time — not whatever the host would hand out today.

Bring your own key (it stays in this tab, same as the main demo). Suggested script: ask find orders for Acme as viewer, switch to operator, ask refund A-1001, then press undo.
